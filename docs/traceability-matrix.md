# Dashboard Refactor — Bidirectional Traceability Matrix

This document is the bidirectional source→target traceability matrix for the **single-canvas modular dashboard refactor** of Ghostfolio. It maps every refactor requirement — the six goals (`G1`–`G6`), the ten refactoring-specific rules (Rules 1–10), the four global implementation rules, the intentional ChatPanel deviation, the behavior-preservation guarantee, and the twelve per-module source→target wrappings — to the target files that implement them (the **forward** table), and maps every new or changed target file back to the requirement(s) and rule(s) it satisfies (the **reverse** table). Together the two tables achieve **100% bidirectional coverage** as mandated by the AAP § 0.8.4 Explainability rule: there are **no orphan targets** (every § 0.5.1 target file appears in the reverse table) and **no unmapped requirements** (every goal, rule, and global rule appears in the forward table). This file is a **sibling** of `docs/decision-log.md` — decisions are cited here by their `DL-` identifier (notably `DL-001` for the ChatPanel deviation) — and it complements the pre-existing `docs/decisions/agent-action-plan-decisions.md`, whose Bidirectional Traceability Matrix section provided the structural template. The forward and reverse tables MUST be updated in lockstep on any file rename or split so the matrix remains the canonical, complete mapping between requirements and implementation.

Introducing a new grid module requires two coordinated edits: a new **forward** per-module source→target row and a new **reverse** row for the wrapper component.
