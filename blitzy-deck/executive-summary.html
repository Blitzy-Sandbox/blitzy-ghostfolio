Single-Canvas Modular Dashboard

Ghostfolio — Route-per-Screen → User-Composable Grid

Every feature becomes an independently placeable grid module, composed on one drag-and-drop canvas and persisted per user.

Executive Briefing · Blitzy Agent Action Plan

The Shift

Before — Route per Screen

  • ~147-line lazy Routes[] table, one tree per screen
  • <gf-header> + <gf-footer> wrap a <router-outlet>
  • Static component trees per page (tabs + outlets)
  • Layout implicit in the route structure

After — Single Canvas

  • One route { path: '', component: GfDashboardCanvasComponent }
  • <gf-dashboard-canvas> fills the viewport
  • Runtime composition via registry + NgComponentOutlet
  • Explicit, per-user, persisted UserDashboardLayout

Behavior-preserving: feature components are wrapped, not rewritten. Existing services (Portfolio, Symbol, AiChat, Rebalancing, FinancialProfile) are reused unchanged.

01

Six Goals

What We’re Building

From grid engine to grid specification — the pillars of the refactor.

The Six Goals

1 · Grid Engine

angular-gridster2 v21.0.1 as the drag-and-drop grid engine (Angular-21 compatible).

2 · Module Registry

A central service registering module types with metadata: name, component reference, min cell dimensions.

3 · Grid Canvas

A single root component rendered at the root route /.

4 · Layout Persistence

New Prisma model UserDashboardLayout + JWT-protected GET/PATCH /api/v1/user/layout.

5 · Module Catalog

Searchable overlay/sidebar of all modules; add via drag or click, remove via a header action.

6 · Grid Spec

12-column grid, fixed (constant px) row height, minimum module size 2×2 cells.

Registry-Driven Composition

How Modules Render

  • Registry maps a module-type key → DashboardModuleDefinition
  • Canvas iterates the persisted GridsterItem[]
  • NgComponentOutlet resolves each component Type at runtime
  • Registry is the ONLY way to add a module type (Rule 3)

Twelve Feature Modules

  • portfolio-overview · holdings · performance · summary
  • investment-chart · market-overview · watchlist
  • fear-and-greed · benchmark · rebalancing
  • financial-profile · ai-chat (deviation)

Wrappers import only their feature component and the shared ModuleShellComponent — never the grid layer or canvas (Rule 1). Data flows exclusively through existing services.

03

Persistence

Per-User Layout Slice

A thin, additive slice on the existing user domain.

Layout Persistence & API

Server Slice (user module)

  • GET /api/v1/user/layout → saved layout, or 404 → null
  • PATCH /api/v1/user/layout → upsert, returns 200
  • AuthGuard('jwt') + HasPermissionGuard (Rule 8); else 401
  • UserDashboardLayout: userId PK/FK, layoutData JSONB, updatedAt, 1:1 User

Client State & Save (Rules 2 & 4)

  • Signal store = single source of truth for positions/sizes
  • Persistence debounced ~500 ms
  • Fired ONLY by grid events (drag/resize/add/remove)
  • Modules never call the save API directly

Permission correctness: getPermissions(role) must GRANT readDashboardLayout / updateDashboardLayout in every role branch, or authenticated users receive 403.

04

Governance

Ten Refactoring Rules

The non-negotiable engineering contract for the refactor.

The Ten Refactoring Rules

  • 1. Modules never import the grid/canvas layer; data via services only
  • 2. Grid state is the single source of truth for positions/sizes
  • 3. Registry is the only way to introduce module types
  • 4. Persistence triggered exclusively by grid events
  • 5. Router preserved; app reduces to a single / route
  • 6. Modules declare min cell dimensions; engine enforces them
  • 7. Chrome uses var(--mat-sys-*, fallback) (D-020)
  • 8. Layout endpoints behind existing auth guards; 401 if not
  • 9. Read schema.prisma first; migration must not conflict
  • 10. Catalog auto-opens on first visit when no saved layout

Risks

And How We Mitigate Them

Anticipated failure modes and the controls that contain them.

Risk & Mitigation Register

Risk Likelihood Mitigation
Lost final change on teardown Medium Debounced persistence flushes on component destroy / navigation (§ 0.7.2).
Role misses new permission grant Medium getPermissions(role) grants read/updateDashboardLayout in every role branch, else 403.
Canvas collapses to zero height Low Full-height host (100vh/flex) since header/footer removed — known gridster gotcha.
Deep links to former paths Low Wildcard redirect to ''; Router infra (ServiceWorkerModule, PageTitleStrategy) preserved (Rule 5).
Zone vs zoneless drag/resize Low gridster v21 retains NgZone.run / runOutsideAngular — compatible with the zone-based bootstrap (§ 0.7.1).
Below-minimum module size Low Dual enforcement: per-item minItemCols/Rows = 2 + itemValidateCallback rejects < 2 (Rule 6).
Migration conflicts with User model Low Additive CREATE TABLE only; virtual back-relation adds no column; no ALTER (Rule 9).

Ship It in Three Steps

  1. Install the grid engine. Run npm install angular-gridster2@21.0.1 — the only new runtime dependency.
  2. Migrate the schema. Run npx prisma migrate dev --name add-user-dashboard-layout after adding the UserDashboardLayout model.
  3. Build & verify. Run npx nx build client && npx nx build api — both must complete without errors.
