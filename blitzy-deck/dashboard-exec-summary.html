Modular Dashboard System

Ghostfolio — Single-Canvas, Drag-and-Drop Dashboard

Every authenticated feature becomes a self-contained, independently placeable grid module — composed by the user and persisted per account.

Executive Briefing · Blitzy Agent Action Plan

Scope at a Glance

  • Paradigm shift. Route-based navigation shell collapses into one drag-and-drop grid canvas at route /.
  • 12 feature modules. Overview, Holdings, Summary, Markets, Watchlist, Portfolio Summary, Transactions, Allocations, Analysis, FIRE, X-ray, and the extracted AI Chat panel.
  • 12-column grid. Built on angular-gridster2@21.0.1 — fixed row height, minimum module size 2×2 cells.
  • Per-user persistence. New Prisma UserDashboardLayout model behind GET/PATCH /api/v1/user/layout.
  • Strictly additive. One new npm package; additive wiring only; existing data services, business logic, and auth guards unchanged.
  • Out of scope. Mobile/responsive layouts, shared/admin-defined default layouts, and multi-user collaboration.

From Routes to One Canvas

Before · Route-Based Shell

  • gf-header tab/sidebar navigation across screens
  • Lazy per-page route table; ** wildcard → home
  • Each feature lives on its own page
  • AI chat embedded in portfolio-page.html:32

After · Single-Canvas Grid

  • Single path: '' route → DashboardCanvasComponent
  • Every feature is a draggable, resizable module
  • Router infra preserved — RouterModule.forRoot, ServiceWorkerModule, PageTitleStrategy, ModulePreloadService
  • AI chat extracted into a first-class grid module

The collapse targets the authenticated in-app surface; authentication, bootstrap, and public routes remain fully operational so JWT login (which the layout endpoints depend on) keeps working.

The Grid Canvas

12 Columns, One Surface

A single drag-and-drop canvas where layout is the only state.

The Grid Canvas

Grid Specification

  • 12 columns (minCols/maxCols = 12)
  • Fixed row height (constant pixel value)
  • Minimum module size 2×2 cells (minItemCols/minItemRows = 2)
  • Below-minimum resizes rejected by the engine
  • Drag and resize enabled

Engine · gridster2 v21

  • angular-gridster2@21.0.1 (Gridster, GridsterItem)
  • Modules rendered via NgComponentOutlet
  • Grid API via viewChild(Gridster).api / initCallback
  • itemChangeCallback / itemResizeCallback drive debounced save
  • Zone-compatible (NgZone retained); ≤100ms visual update

The GridsterItem[] array on the canvas is the single source of truth for module positions and sizes — module components hold no layout state.

02

The Module System

Registry · Catalog · Isolation

One registry to introduce them, one catalog to compose them.

Registry & Catalog

ModuleRegistryService

  • providedIn: 'root'; holds Map<string, ModuleDefinition>
  • Exposes register / get / getAll / has
  • All 12 module definitions registered in the constructor
  • ModuleDefinition { key, displayName, component, minItemCols, minItemRows, icon? }
  • The only mechanism to introduce a module type (no ad-hoc insertion)

ModuleCatalogComponent

  • MatFormField search filters a MatList/MatCard of modules
  • Add by click or drag
  • Placed at the next available grid position (first-fit)
  • Remove via a module-header action
  • MatSidenav / CDK overlay; autoOpen input drives first visit

Module Isolation & Wrappers

  • Each feature is hosted by a thin wrapper component rendered via NgComponentOutlet.
  • Wrappers add MatCard chrome — header title + remove MatIconButton.
  • Wrappers must not import the canvas layer; data flows only through existing services.
  • All grid chrome uses MD3 token discipline (D-020): var(--mat-sys-<token>, <hardcoded-fallback>).
  • 12 modules — gf-home-overview, gf-home-holdings, gf-home-summary, gf-home-market, gf-home-watchlist, gf-portfolio-summary, gf-activities-page, gf-allocations-page, gf-analysis-page, gf-fire-page, gf-x-ray-page, and the extracted app-chat-panel.

Existing feature components are referenced, not modified — the AI Chat panel’s inline embed at portfolio-page.html:32 is removed and re-hosted as a selectable "AI Chat" module (a documented, intentional deviation).

Persistence & Onboarding

Layout That Follows the User

Saved on every change, restored on every visit.

Per-User Layout Persistence

Data & API

  • Prisma UserDashboardLayout — userId @id (FK), layoutData Json, createdAt, updatedAt, cascade delete
  • User gains a dashboardLayout back-relation (mirrors FinancialProfile)
  • GET / PATCH /api/v1/user/layout
  • AuthGuard('jwt') + HasPermissionGuard → 401 / 403
  • X-Correlation-ID logging; class-validator DTO size caps

Client Pipeline

  • DashboardLayoutService wraps GET / PATCH
  • Versioned JSONB — { schemaVersion, items: [{ moduleKey, x, y, cols, rows }] }
  • queueSave() → RxJS Subject + debounceTime(500) + switchMap
  • Persistence is grid-event-driven only (drag / resize / add / remove)
  • Module components never call the save API directly

Onboarding & First Visit

  • GET /api/v1/user/layout returns 404 when no record exists.
  • The client translates 404 → null (mirrors the FinancialProfileService pattern).
  • A null layout → blank canvas with the module catalog auto-opened.
  • A returning user’s saved layout hydrates the grid on app init.
  • The AI Chat panel appears here as a first-class, selectable module.

New user → blank canvas + catalog open; returning user → saved layout loaded — the two acceptance scenarios for onboarding.

Feature Rules

Risk & Mitigation Register

Risk Likelihood Mitigation
Route collapse degrades router infrastructure Low Preserve RouterModule.forRoot, ServiceWorkerModule, PageTitleStrategy, ModulePreloadService; single / route only.
Module↔canvas coupling / layout-state leak Low Module isolation rule: wrappers via NgComponentOutlet, no canvas imports; GridsterItem[] is the single source of truth.
PATCH write-storm on drag/resize Medium RxJS debounceTime(500) + switchMap; persistence fires only on grid state-change events.
Unauthenticated / cross-user layout access Low AuthGuard('jwt') + HasPermissionGuard; userId sourced from request.user.id; 401 when unauthenticated.
Oversized JSONB payload (DoS) Low class-validator DTO — @ArrayMaxSize, @MaxLength, @IsInt/@Min size caps.
Migration conflict with User/FinancialProfile Low schema.prisma read first; additive CREATE TABLE; mirrors the FinancialProfile side-table with cascade delete.
gridster2 / zone.js incompatibility Low v21 retains NgZone.run/runOutsideAngular; compatible with provideZoneChangeDetection(); ≤100ms updates.

Get Started in Five Steps

  1. Read the Agent Action Plan. Scope, rules, and acceptance gates live in the PR description (AAP § 0.6–0.8).
  2. Install + migrate. npm install picks up angular-gridster2@21.0.1; run npx prisma migrate dev --name add-user-dashboard-layout.
  3. Explore the grid system. apps/client/src/app/dashboard/ holds the canvas, registry, catalog, layout service, and 12 module wrappers.
  4. Trace the layout endpoints. apps/api/src/app/user/user-dashboard-layout.{controller,service}.ts back GET/PATCH /api/v1/user/layout.
  5. Run the stack. npx nx build client + npx nx build api; on first visit you get a blank canvas with the catalog auto-opened.
