Modular Dashboard Canvas

Ghostfolio v3.0.0 — Single-Canvas Workspace Refactor

Every screen becomes a draggable, resizable module on one user-composable canvas — with each arrangement persisted per user.

Executive Briefing · Blitzy Agent Action Plan

Scope at a Glance

  • Single modular canvas. The multi-route shell collapses to one root route / rendering a 12-column angular-gridster2 grid — fixed row height, 2×2 minimum module footprint.
  • Every feature becomes a module. Overview, holdings, summary, watchlist, market, the AI chat panel, and the portfolio tabs (analysis, activities, allocations, FIRE, rebalancing, X-ray) are now independently placeable modules.
  • Central registry + searchable catalog. One ModuleRegistryService is the authoritative catalog of module types; a searchable overlay adds them by click or drag.
  • Per-user persistence. Layouts save to PostgreSQL through GET/PATCH /api/v1/user/layout, backed by a new UserDashboardLayout model.
  • Strictly additive & preserving. The Router, service worker, auth guards, and all data services are preserved unchanged; exactly one new dependency — angular-gridster2@21.0.1.

Business Value

For Users

  • A workspace they compose themselves — drag, resize, add, remove.
  • Their arrangement is remembered and restored on every visit.
  • First visit auto-opens the catalog for instant composition.

For the Business

  • 100% reuse of existing features — zero feature rewrites.
  • Low-risk, additive delivery: one dependency, one new table.
  • An extensible platform — new modules plug into one registry.

The AI chat panel (app-chat-panel) becomes a first-class, selectable module — intentionally superseding its hard-coded embed in the portfolio page.

Route Shell → Single Canvas

Before

  • ~22 lazy-loaded routes + wildcard redirect
  • gf-header top-navigation chrome
  • gf-footer chrome
  • Per-screen *-page.routes.ts trees

After

  • One route / → DashboardCanvasComponent
  • <router-outlet> retained to host the canvas
  • Router, ServiceWorker, PageTitleStrategy, ModulePreloadService preserved
  • components/header/** removed; no extra routes added

The Router is preserved, not removed (Rule 5) — only the route table contracts to a single /.

API & Database

API Surface

  • GET /api/v1/user/layout — 404 translates to null
  • PATCH /api/v1/user/layout — class-validator DTO
  • AuthGuard('jwt') + HasPermissionGuard (Rule 8) — 401 when unauthenticated
  • Current user via @Inject(REQUEST); mirrors user-financial-profile

Prisma Model

  • UserDashboardLayout keyed by userId @id
  • layoutData Json → native jsonb
  • 1:1 back-relation on User (Rule 9, Prisma 7)
  • onDelete: Cascade; one new migration

The absence of a row is the canonical “new user / blank canvas” signal — no data backfill is required.

Risks

And How We Mitigate Them

Anticipated failure modes and the controls that contain them.

Risk & Mitigation Register

Risk Likelihood Mitigation
Drag/resize jank beyond the 100 ms budget Low angular-gridster2 v21 honors NgZone for zone.js apps; interaction runs outside Angular until commit.
Deep links break on route collapse Medium Router infrastructure preserved (Rule 5); the single / canvas restores saved state; no additional routes introduced.
Layout JSON shape drift Low A shared UserDashboardLayout interface plus a class-validator DTO validate every payload on both client and server.
Module↔grid coupling regressions Low Wrappers never import the grid (Rule 1); the grid is the single source of layout truth (Rule 2).
Unauthenticated layout access Low AuthGuard('jwt') + HasPermissionGuard (Rule 8); unauthenticated requests receive 401.
Confusing empty first visit Medium With no saved layout, the catalog opens automatically over a blank canvas (Rule 10).
Inconsistent grid-chrome styling Low All chrome uses the var(--mat-sys-token, fallback) pattern (Rule 7); fallbacks are the load-bearing values.

Onboarding

Where to Start

A 5-minute orientation for new engineers.

Get Started in Five Steps

  1. Read the Agent Action Plan. Scope, the 10 engineering rules, and the 4 project rules live in the PR description.
  2. Install & migrate. Run npm install (adds angular-gridster2@21.0.1) then npx prisma migrate dev to create UserDashboardLayout.
  3. Explore the canvas. Start in apps/client/src/app/dashboard/ — canvas, registry, layout service, catalog, and module wrappers.
  4. Run the stack. npm run start:dev, open /, then drag, resize, add, and remove modules.
  5. Review the contract. Re-read registry (Rule 3), persistence (Rule 4), and router (Rule 5) before extending the system.

Questions? Drop them in the #modular-dashboard Slack channel.
